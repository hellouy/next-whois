The app is running cleanly. Here's a summary of everything that was fixed:

Root cause: The admin stats were undercounting searches in two ways.

Fix 1 — save-search-record.ts
Logged-in users previously had a DELETE+INSERT upsert, meaning searching the same domain 5 times left only 1 record. Now both logged-in and anonymous users always INSERT a fresh row — every single search event is counted.

Fix 2 — User history display (user/search-history.ts)
Since logged-in users now accumulate multiple records per domain, the personal history page uses DISTINCT ON (LOWER(query)) to deduplicate and show only the most recent search per domain. The count also uses COUNT(DISTINCT LOWER(query)). So the user-facing history remains clean.

Fix 3 — Admin stats (admin/search-records.ts)
匿名查询 and 已登录 were computing "distinct domains whose last search was by anon/logged user". Now they simply count raw events: COUNT(*) WHERE user_id IS NULL and COUNT(*) WHERE user_id IS NOT NULL. These two numbers will now add up exactly to 总搜索次.

Fix 4 — Tooltip text
Updated the card tooltips to say "匿名用户的总查询次数（每次查询均计入）" and "已登录用户的总查询次数（每次查询均计入）", so it's clear these are total event counts.

Going forward, every lookup by any user — logged-in or anonymous, repeat or first-time — will be recorded and counted.
